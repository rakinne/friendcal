# Design: FriendCal — The Hub for Tight-Knit Friends to Align

## Problem Statement
Friend groups plan Friendsgivemas-style gatherings over fragmented iMessage threads. Coordinating dates requires tagging individuals, free-form replies ("Nov 20,21 Dec 12,19"), manual polls (Nov 21st / Dec 5th / Dec 12th), and re-asking people who ignore or reply late. Messages like “Weekend of the 12th is my godson’s bday” and open-ended park invites (“taking the kids to the park, y’all free to tap in”) get lost. Existing tools fail: Partiful/Posh are browse-oriented with false “Going” signals (people mark Going to see guest list, never show), never used to *organize* with close friends. The result: slow convergence, repeated poking, surprise plans that risk spoiling if made visible.

## What Makes This Cool
The “whoa” is a live hub, not a poll link. Open FriendCal and a T-Mobile myFaves-inspired rotary wheel of 5-10 friends’ faces spins — nostalgic, tactile, clearly alive. Tap a face to see what they’re up to and where they’ll be. Propose a gathering (“Friendsgivemas”) → fire “Request for Times” to your network via Instagram-like Send Separately / Send in New Group — they tap free slots natively (FriendCal IS the calendar) and a heatmap converges in real-time. Lock Nov 21st and it *blooms* into Partiful-style invite art, potluck sign-up, playlist, countdown — hype, not just a calendar hold. Buy an NBA/concert ticket elsewhere? “Add to FriendCal” → friends see a Tag Along card with deep links to get tickets and one-tap join. A FriendCal ghost delights and re-engages (haunts if you’ve been quiet, celebrates convergence). Privacy is embedded: surprise brunch for Jalen is a Stealth Hold — to Jalen it looks like identical grey “Busy” (indistinguishable from dentist/focus), to everyone else it’s full-fidelity invite art.

## Constraints
- First users = this tight-knit group: weddings, kids’ birthdays, 4th of July together — high trust, low tolerance for app-switching.
- iMessage is planning home; Partiful/Posh are ticket-browse with impersonal/false signal. Must beat “just text” on speed.
- Friends do NOT maintain Google/Apple Calendars reliably; FriendCal must be calendar of record.
- Surprise events must be un-guessable even after seeing multiple busy blocks — no correlation leakage via shared busy times.

## Premises
1. **FriendCal as calendar of record** — validated: user said “I don’t think my friends keep track with Google Cal and Apple Calendar. Ideally, THIS would be their calendar.” Conventional “sync once” is wrong for this cohort.
2. **Dual-purpose availability (pre-commit)** — marking free in one Proposal updates global profile; future Proposals see you as held at that time. Prevents 10am vs 10:15am double-book. User explicitly requested this.
3. **MyFaves wheel as primary nav** — rotary of individuals/profile pictures showing network liveness; tap to see what’s new. Creates “people are actively using it” signal.
4. **Tag Along** — ticket acquired elsewhere can be added; friends piggyback with one tap + deep links to ticket sources.
5. **Partiful-inspired hype** — auto-generated invite art/event presentation on convergence (user loves Partiful’s presentation).
6. **Poke** — lightweight nudge (Facebook Poke callback) when someone ignores availability request, replacing “@t’s & tagging 3x” in iMessage thread.
7. **Stealth privacy via indistinguishable Busy** — excluded viewer sees generic Busy block, no host/avatar, uniform styling; no inference from synchronized busy across multiple friends.

## Approaches Considered
### Approach A: Minimal Viable Proposal
Proposal → Request for Times → heatmap → lock + Busy update. Wheel is nav only. No tickets, no art. Fastest to replace iMessage poll/Google Form, but misses wow/hype and re-engagement loop.

### Approach B: Ideal Hub (Chosen)
A + Tag Along + Partiful hype generation + dual-purpose pre-commit + Stealth Holds + Poke + Ghost. The “seamlessly tag along + seamlessly boost alignment” hub user described. Single place to see where closest friends/communities will be and tap in. Balances delight and build scope.

### Approach C: Live Ghost World
B + ghost as autonomous agent — pulses when someone nearby says “park now,” haunts inactive friends, narrates convergence (“3 friends converging on Nov 21st!”). More viral/fun, heavier to build, risks feeling gimmicky.

## Recommended Approach
Approach B. Rationale: user validated premise that FriendCal *is* the calendar (no sync moat to build), wants Tag Along, wants Partiful art, and privacy is non-negotiable after surprise-brunch example (Mica/Jalen Nov 7 Mardi Gras Tuesday). Wheel + Ghost deliver the “whoa” without Approach C’s complexity.

Core model:
- **Entities**: User, Circle/Group, Proposal {title, window, requestRecipients via Send Separately/New Group}, AvailabilitySlot {user, timeRange, sourceProposal}, BusyBlock {user, timeRange, visibility: public|stealth, hiddenFrom: []}, Event {from locked Proposal, with Partiful art, potluck/playlist}, TicketTap {sourceUrl, event, tagAlongLinks}.
- **Availability heatmap**: recipients tap free slots in-proposal; each tap writes to profile availability (global). Heatmap recomputes; show green/yellow/red Saturdays.
- **Stealth logic**: On read for excluded user, Event/Proposal title/location/attendees stripped → render as generic Busy. No avatar stack, no “Mica’s event” label. Same component/style as any manual Busy hold to prevent grokking.
- **Wheel**: home screen rotary, 5-10 faces, unread pulse for new Tap-In / locked Event / Poke. Tap → profile sheet: upcoming busy (sanitized), open Tap-Ins, tagged events.
- **Hype**: on lock, generate invite art template (title, date, venue map, potluck list), shareable image, countdown.

## Open Questions
- Should manual Busy holds be user-created or only derived from Proposals/Events? (Impacts distinguishability)
- Poke rate limits / mute? Avoid spam in tight-knit group.
- Wheel size limit? What happens with 20+ friends — pages or favorites subset?
- Ticket deep-link sources scope (Ticketmaster, Posh, Partiful?) — start with manual URL vs integration?

## Success Criteria
- Friendsgivemas flow from iMessage screenshots completes in <2 minutes vs original multi-day thread + poll + “poll is up / 6 Replies / I thought X was busy” confusion.
- Park Tap-In (“kids to park”) gets at least one response vs zero in iMessage — measured by Tag Along taps.
- Surprise Stealth Hold: excluded user cannot distinguish surprise from generic Busy in blind test (no grok after 3 coordinated busy blocks).
- Wheel DAU: user opens to check wheel without having a Proposal to respond to.

## Distribution Plan
iOS app (SwiftUI) + optional web for invite art sharing. TestFlight for founding friend group (first users are this group). Existing pipeline: branch `codex/*`, conventional commits, docs/ kept current.
